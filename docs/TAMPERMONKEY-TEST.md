# 篡改猴验收步骤（0.5.3）

这份清单用于确认脚本在真实 Chrome + 篡改猴中的表现。请按顺序测试，结果记为“通过／失败／未测”；下面列出的是预期结果，已反馈的实测记录见文末。

## 一、准备与安装

1. 暂时停用暴力猴里的发行信号，以及篡改猴中重复的旧副本，保证只有一份脚本运行。
2. 打开篡改猴管理面板，编辑原来的发行信号，将 [release-signal.user.js](../release-signal.user.js) 的**完整代码**替换进去并保存。确认开头版本为 `0.5.3`，不要另建同名副本。本地未发布的版本不会通过 GitHub 自动更新取得。
3. 保持篡改猴的**沙盒模式为“默认”**，不为本次测试调整“内容脚本 API”等其他全局选项。
4. 如果 Chrome 提示需要允许用户脚本，在浏览器的“扩展程序 → 管理扩展程序 → 篡改猴 → 详细信息”中开启“允许运行用户脚本”。这是浏览器的执行权限，与篡改猴沙盒模式不同，见[官方说明](https://www.tampermonkey.net/faq.php?locale=en&q=Q209)。已经允许时不必改动。
5. 准备自己的 TMDB Token；如要测试 API key，也准备对应的 v3 key。确认能从 TMDB 设置重新取得，后面会测试删除与重新保存。**无需导出管理器数据或分享凭据。**

记录本次环境：

```text

系统版本：
Chrome 版本：
篡改猴版本：
脚本版本：0.5.3
“关于”显示的运行模式：
沙盒设置：默认
可连接的 API 地址：
```

Chrome 与篡改猴版本请填写实际值；本次已反馈的环境为 Chrome 157.0.8103.39 + 篡改猴 5.5.1。

## 二、启动与凭据

### T01 启动和运行信息

打开[肖申克的救赎](https://movie.douban.com/subject/1292052/)，重新加载页面。点击状态行，再点击“关于”。

**预期：** 资料区下方只有一份状态行；关于显示 `0.5.3`、Tampermonkey、管理器版本及 `raw／js／dom` 中的一种模式。默认设置下不再提示启用隔离模式。未配置时显示“请设置 TMDB”；已配置时可以查询或使用缓存。TMDB 标志、来源与非背书声明正常。

### T02 升级保留和首次保存

已有配置时，先打开设置，确认凭据类型与此前保存的 API 地址保留，刷新可查询；不要为了测试先删除配置。没有配置时，选择 Token，点击“设置并查询”，在浏览器原生输入框中填写自己的 Token。

**预期：** 密钥不会回填到网页；首次输入框为空，验证成功后自动查询。重新加载后仍能使用保存的配置。首次配置默认地址为 `api.tmdb.org`；已有配置明确保存的地址保持不变。已有配置的用户可在 T12 删除后补测首次保存。

### T03 取消输入和认证失败

打开设置 →“替换凭据”，先取消原生输入框；再次替换，填写假值 `release-signal-invalid-token`，等待验证结果。

**预期：** 取消不会改动原配置。假值应提示认证失败，设置窗口保留；点击设置中的“取消”，再刷新，仍能使用原来的正确凭据。失败不能显示成“暂未查到发行记录”。重新打开设置也看不到原密钥。

### T04 API key 与两种设置入口

在豆瓣详情页，通过篡改猴扩展菜单的“发行信号：设置 TMDB”打开设置，确认与页面按钮打开的是同一套界面。选择 API key（v3）并保存自己的 key，查询后重新加载，再切回 Token。

**预期：** 更换凭据类型时重新输入并验证；两种类型都能保存、查询与刷新。没有 API key 时，将此项标为“未测”，不要把 Token 填入 API key 栏。

### T05 API 地址切换

保留当前凭据类型，将 API 地址切换到另一个预设地址，点击“保存并查询”；重新打开设置和重新加载页面，检查地址，再恢复常用地址。

**预期：** 沿用现有凭据，不再次弹出密钥输入框；验证成功后才保存地址并查询。另一个地址连接失败时，提示连接／超时错误并保留原配置，不算切换成功。只有两个预设 HTTPS 地址可选。记录各地址能否连接，网络不通与脚本功能失败分开记录。

## 三、显示与数据

### T06 两级折叠与新版排版

在电影页依次展开状态行、“全部发行记录”，再分别收起。用 Tab 聚焦两层标题，试用 Enter 或空格切换；在浏览器 100%、110%、125% 缩放和窄窗口下各看一次。

**预期：**

- 收起只有圆点和一行文字，如“已有发行记录 · YYYY-MM-DD”；窄窗口允许省略，不挤成多行。
- 两层箭头都是细线样式，随展开／收起改变方向，没有额外的黑色实心三角。
- 第一层显示 Web／实体摘要；第二层才显示完整记录。展开向下推开内容，不遮住豆瓣原页面。
- 摘要标签间距较紧凑；已到日期为灰绿，未来／未知状态为较浅的灰色。
- 明细上方是“查询／缓存信息 · 结果仅供参考”和 TMDB 来源两段辅助文字；窄窗口可自然换行，没有额外独占一段的“结果仅供参考”。
- 表头、类型／集号、日期及季终标记不拆行；长地区、片名和说明可以换行，空间不足时在表格内横向滚动，不撑破豆瓣页面。

### T07 电影日期与来源

打开[挽救计划](https://movie.douban.com/subject/35010610/)，展开完整记录，点击 TMDB 来源核对 Digital／Physical 日期。再找有未来日期或无记录的电影查看。数据会变化，以测试当天来源中的记录为准。

**预期：**

| 记录情况 | 收起文字与摘要 |
| --- | --- |
| 至少一类有日期已到的记录 | “已有发行记录 · 最早已到日期”；另一类的未来日期不能覆盖它 |
| 只有未来记录 | “等待发行 · 最早未来日期” |
| 没有有效发行记录 | “暂未查到发行记录”，不附猜测日期 |

Web／实体分别显示“已发行 · 日期”“预计 · 日期”或“暂未查到发行记录”。今天算日期已到；来源只标注年月日时，脚本不擅自增加或减去一天。院线／首映／电视日期不作为 Web 或实体证据。若找不到某种数据样例，记录“未测”。

### T08 剧集识别与进度

依次查看以下已反馈过的页面，核对来源中的剧集及季数：

| 页面 | 检查重点 |
| --- | --- |
| [月光骑士](https://movie.douban.com/subject/26358318/) | TMDB 仍只有一个普通第一季时，自动选择第一季 |
| [黑帮领地第二季](https://movie.douban.com/subject/37403692/) | IMDb 指向单集时，能定位所属剧集及季 |
| [流人第六季](https://movie.douban.com/subject/36689816/) | 同上，不能错误回到其他季 |

**预期：** 最近一集、下一集、日期和 TMDB 来源对应当前季。只有季终标记、完整集数和全部已到日期都有依据时才显示“本季完结”；仅没有下一集日期不代表完结。遇到来源缺失或冲突，应说明原因、要求确认，不能按片名猜测。

### T09 临时切季与剧集表格

打开[绅士们第一季](https://movie.douban.com/subject/35370747/)，切到第二季，展开全部播出记录；缩放、收窄窗口，再重新加载页面。

**预期：** 切季后摘要、明细和链接一起切换，`S02E01` 等集号、日期不拆行。重新加载后按豆瓣当前条目重新判断，恢复第一季，不能记住临时查看的第二季。季数、最近一集等标签本身不换行。

## 四、缓存、跨页与重启

### T10 缓存、刷新和菜单

成功查询电影后展开明细，记录查询时间并重新加载。点击页面“刷新”，也试一次扩展菜单“发行信号：刷新当前作品”；最后使用“清空发行记录缓存”。

**预期：** 重新加载优先显示有效缓存，保留原查询时间；手动刷新后时间更新，加载中按钮不可重复点击。清空缓存后重新查询，凭据仍保留。页面上只存在一份面板；电影与剧集都能刷新。

### T11 跨标签页修改

打开两个详情页 A、B。在 B 将 Token 换为自己的 API key，或换成另一份不同的有效凭据。返回 A，先不要重新加载，打开设置查看类型，再手动刷新。也可在 B 切换到能连接的另一 API 地址，返回 A 检查地址和刷新。

**预期：** A 同步最新配置并提示已同步，刷新可查询；不能继续显示旧类型／旧地址。**同一份 Token 原样保存不能证明跨页换密钥通过。** 没有第二种有效凭据时，换密钥子项标“未测”，仍要测地址同步和下一项删除。无需查看或截图网络请求头。

### T12 跨标签页删除与重新配置

在 B 打开设置，点击“删除凭据”；返回 A，等待同步，并尝试管理器菜单“刷新当前作品”。随后重新加载 A、B，再保存正确凭据，恢复正常使用。

**预期：** 两页均显示“请设置 TMDB”，页面刷新按钮不可用，管理器菜单也不会使用旧凭据继续查询；等待或重新加载都不会恢复旧配置。重新保存成功后，另一页可以同步配置并手动查询。此时补测 T02 的首次保存流程。

### T13 浏览器重启

确认正确凭据已保存。先保存其他工作，再通过 Chrome 菜单“退出”，重新打开浏览器和详情页；新建另一个详情页，也检查一次。

**预期：** 无需重新输入凭据或调整沙盒即可显示缓存／查询，设置、刷新和新标签页均可用。若只有反复刷新、停用再启用管理器后才能恢复，此项记“失败”，不要记为全部通过。

### T14 运行范围与信息展示

打开[豆瓣电影首页](https://movie.douban.com/)及影片的“全部影评”页，回到详情页再查看“关于”和设置。

**预期：** 非详情页没有发行信号面板，详情页仍正常。关于只显示管理器、版本、模式等信息；状态、明细和设置都不展示已保存的密钥。来源链接指向 TMDB 的对应电影／剧集及季。无需导出存储、HAR 或完整控制台日志来反馈结果。

## 五、遇到相应条件时再测

- **C01 慢请求与配置变更：** A 正在查询时，立即在 B 删除／修改配置。等待查询结束，A 不得被旧结果恢复。来不及操作时记“未测”，不必反复请求制造延迟。
- **C02 网络失败：** 自然遇到连接失败或超时时，检查错误是否明确；已有结果应标为旧数据，不得将错误当作无发行记录，刷新按钮最终可再次使用。仅把豆瓣页开发者工具设为 Offline，未必能阻断管理器后台请求，不以此作为可靠断网测试。
- **C03 跨日：** 有未来记录的页面自然跨过本地零点，或跨日后返回原标签页，检查状态是否按新日期更新；不能必须手动刷新才改变。无需调整系统时间来测试。

429、异常 JSON、严格日期、缓存过期、取消后迟到结果、IMDb 缺失／冲突等边界由自动化测试补足，不要刻意触发真实服务限流或改动系统／代理配置。真实豆瓣若出现安全校验，先停止该页测试并记“未测”，不要绕过。
